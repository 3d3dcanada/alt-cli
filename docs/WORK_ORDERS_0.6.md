# Alt 0.6 beta work orders

Scope: complete cloud-executable work from the readiness review. Physical PC
qualification and observed human usability remain separate acceptance gates.
Full access and the user's model selection remain available and unchanged.

## 1. Reliable task execution

- Make model instructions reflect the exact tool focus and configured checks.
- Bring check discovery into project setup; never silently execute suggestions.
- Give empty-check, syntax-error and failed-check responses actionable recovery.
- Validate with protocol tests and complete 20 × 5 development plus 4 × 5
  held-out attempts on explicitly selected uncensored weights. Freeze each
  campaign's executable, settings and fixtures. Report failures and timeouts.
- Do not promote a model preset from incomplete or unsuccessful evidence.

## 2. First successful task

- Add an isolated, repeatable practice project reachable from Home and the CLI.
- Provide a genuine failing seed and independently pinned behavioral checks.
- Explain inspect, repair, check and undo with labelled actions and saved progress.
- Test the complete journey through a real PTY and persisted evidence, including
  restart, small terminals and an unavailable dependency. No real user project
  may be overwritten. Human sessions are explicitly unperformed here.

## 3. Useful bounded memory

- Preserve current requirements and evidence before historical notes.
- Select complete, readable source excerpts with explicit omission accounting.
- Keep tool guidance outside any truncated memory block.
- Measure retrieval after interruptions, edits and distracting history; test
  representative live continuation tasks with the same selected model.
- Distinguish recall/retrieval measurements from coding success and native context.

## 4. Sustained recovery

- Exercise repeated stream disconnects, cancellation, runtime/engine loss and
  interrupted downloads; retain timing, cleanup and restart results.
- Extend actual workload soak, rather than counting idle launches as inference.
- Fix demonstrated defects and retain regression tests that would catch them.

## 5. Installable release and PC handoff

- Produce a versioned Linux package and verify its exact installed executable.
- Make backup, update and rollback understandable and test prior-version recovery.
- Prefer GitHub identity-backed artifact attestations for a reproducible public
  release without generating an unmanaged production private signing key.
- Provide a PC test kit that records machine/build/model identity and preserves
  failures; only selected uncensored models may be used for live tests.
- Run formatting, strict Clippy, Rust tests, terminal journeys, both supported
  Goose protocol fixtures, package checks and remote CI.

## Reporting

Record delivered changes, exact commands, measured results and remaining gates
in `IMPLEMENTATION_0.6.md`. A failed model matrix is a completed measurement, not
a passing acceptance gate. A cloud run cannot stand in for a GTX 1070 test or a
human participant. Keep old evidence immutable.
